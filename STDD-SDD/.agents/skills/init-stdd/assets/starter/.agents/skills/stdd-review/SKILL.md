# 审查变更

1. 根据用户请求、PR 目标或仓库约定确定范围。审查已提交分支时，用 `python3 -B scripts/git_range.py --merge-base <目标引用> <候选引用>` 定位增量，再读有影响的 diff。审查工作区改动时查看已暂存和未暂存的相关差异。
2. 读取目标分支的评审规则（如有）和已确认的规格。对照 `REQ-*`、`AC-*`、测试与证据，优先核查边界、兼容性、失败路径、状态和副作用。检查删改的断言及 CI 是否有明确理由。
3. 核对测试结果所对应的提交与当前候选。缺少证据时，按任务范围复跑关键用例或列出待验证项。
4. 按影响给出发现，附文件和行号、受影响场景及用户可观察的后果。区分已确认缺陷与仍需复核的问题。Git 比较只读取现有引用，维护分支的操作沿用项目流程。
