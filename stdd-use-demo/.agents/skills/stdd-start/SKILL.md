# 开始一项变更

1. 读 `AGENTS.md`、`docs/engineering.md` 和需求来源。定位能力规范、接口契约、相关测试及需要保留的行为。若仓库使用 Git，先识别当前工作区和任务所基于的提交。
2. 已有变更目录时直接复用。新变更需要独立文档时，用 `python3 -B scripts/new_change.py <变更ID> '<标题>'`。产品、设计、研发和测试需要共同评审时加 `--roles`，只需补技术设计时加 `--design`。沿用项目已有 ID，或为新目录选择一个可辨认的未用编号。
3. 写清当前行为、目标行为、范围和非目标。给受影响的 `REQ-*` 确定 `AC-*`，把尚未确认的业务决定和受影响的切片写进 `change.md`。已明确的小变更可使用工单或 PR 记录。
4. 在 `tasks.md` 排好第一个可验收切片，写明定向测试或人工验证入口。下一步执行时沿用已确认的规格和仓库的分支约定。
