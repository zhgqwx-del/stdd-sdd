# 工程约定

## 规格与验收

- `specs/<capability>/spec.md` 记录已交付的可观察行为。将待确认的改动写在 `changes/<id>/`，随实现、测试与决策记录一同评审。
- 需求与验收分别使用 `REQ-<领域>-<序号>`、`AC-<领域>-<序号>`。领域码使用大写英文字母或数字，可用短横线连接。用三级标题记录 ID，并在每个场景下用 `关联` 指向需求。
- 规格、设计、任务和验收都引用相同的 ID。`test-plan.md` 记录要验证什么，`verification.md` 记录实际观察和受测版本。
- 在可运行的旧实现上先验证新增用例能捕获差异，再实现和复跑。需要手工验收时记录环境、操作、预期和实际结果。

## 团队交付

- 影响用户结果的取舍写入 `change.md` 并由相应负责人确认。并行变更按最新候选提交重跑受影响的检查。
- 应用启动、测试、构建和 CI 使用当前项目的实际技术栈。接入自动检查时，本地和 CI 可复用同一套命令。
- 开发前在 `tasks.md` 明确方案和确认记录。基线、分支、同步及提交整理按[项目 Git 约定](stdd/git-workflow.md)执行。
- 从 [角色导航](stdd/roles.md) 找到交接入口。完成后按项目流程更新现行规格及交付记录。
